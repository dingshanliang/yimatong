# 轻量验真与跨区判定的可靠信号边界

## 研究问题

在不引入专用防伪材料、硬件或强制实名的标准产品中，二维码状态、扫码次数、时间、设备、IP
和地理位置分别能支持什么判断？哪些消费者表述和自动处置超出了证据能力？

## 结论摘要

标准产品应把这套能力定义为 **“码状态核验 + 异常使用风险提示 + 跨区线索闭环”**，而不是商品真伪鉴定。

- 平台能可靠说明的是：该标识符是否由平台签发、当前生命周期状态是什么、平台观察到了哪些扫码事件。
- 序列化二维码能提高追踪粒度，但普通条码可被复制。GS1 明确指出，即使是序列级商品条码也可以被复制和重印；只有把签名数据与产品实例上的额外安全特征强绑定，才能提供更高的实物真实性保证。[GS1 Digital Signatures, §2、§3](https://ref.gs1.org/guidelines/digital-signatures/)
- 扫码次数、时间、IP、浏览器特征和地理位置适合组合成风险信号。NIST 将 IP、地理位置、请求时序、浏览器元数据和使用速度列为风险型或自适应判断的辅助特征，而不是独立的有效认证器。[NIST SP 800-63B-4, §3.2.2、§5.3](https://pages.nist.gov/800-63-4/sp800-63b.html)
- 跨区扫码只能先形成“偏离预期流向”的调查线索。要理解一次供应链事件，GS1 EPCIS 要求结合 what、when、where、why（以及 2.0 中的 how）等业务上下文；一个消费者位置点本身不包含出货、退货、转售、旅行等背景。[GS1 EPCIS and CBV Implementation Guideline](https://ref.gs1.org/guidelines/epcis-cbv/2.0.0/)

因此，消费者端不得承诺“绝对正品”，运营端不得因单次重扫或单次跨区自动认定假货、窜货或处罚渠道。

## 推荐的产品判定模型

### 1. 消费者端验真状态

消费者页面只展示可由平台事实支撑的状态：

1. **查无此码**：标识符不在当前租户的签发记录中，阻断正常页面和权益。
2. **未激活 / 冻结 / 作废**：展示准确生命周期状态，阻断相应业务能力。
3. **有效，首次记录**：使用“这是本系统记录的首次查询/验证”。
4. **有效，已有记录**：展示首次记录时间和累计次数，并提示消费者在非本人重复查询时联系品牌方。
5. **有效，存在异常使用信号**：使用“该码存在异常使用记录，建议核对购买渠道或联系品牌方”，不要直接显示“假货”。

普通二维码下不使用以下文案：

- “首次扫码，确定为正品”
- “官方绝对防伪 / 100% 正品”
- “已扫码，所以是假货”
- “系统已确认复制码”

若未来要把承诺从“轻量验真”提升到更高保证，单纯增加签名仍不够。GS1 指出，只校验描述实体标识符的签名，仍不能确定该标识符是否真的对应眼前这件实物；需再绑定只能从该物理实例读取的安全特征，例如水印、全息、微缩印刷或 UV 隐码。[GS1 Digital Signatures, §2–§4](https://ref.gs1.org/guidelines/digital-signatures/)

### 2. 跨区风险分级

先区分三个概念：

- **预期区域**：由码段分配、经销商和有效流向记录确定的业务基线。
- **观察位置**：一次扫码所报告的位置，必须连同来源和不确定性保存。
- **窜货结论**：运营人员结合订单、物流、渠道授权和调查材料作出的业务处置结果。

建议分级：

| 等级       | 触发示例                                                                                                                        | 系统动作                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 信息不足   | 无定位授权；只有低精度 IP 地理位置；定位精度范围与预期区域相交；预期区域未配置                                                  | 保留观察，不生成“跨区”结论；可进入数据质量待办                         |
| 低风险偏离 | 单次 IP 粗定位落在区域外，或单次浏览器定位略超边界但精度/边界容差不足                                                           | 记录偏离，不通知消费者，不自动建高优先级案件                           |
| 中风险线索 | 高精度授权定位明显超出预期区域，且与有效流向记录不符；或同一地区持续出现多个码的偏离                                            | 建立可调查线索，关联经销商、码批次、时间窗口和证据质量                 |
| 高风险线索 | 同一实例码在不可能通行的时间窗口内出现在相距较远的高质量位置；或异常涉及多个网络/浏览环境并持续扩散；或与可信出入库事件直接冲突 | 提升案件优先级，可临时限制权益、防刷或人工冻结；仍不自动认定窜货或处罚 |

“同一序列化标识在同一时间或重叠时间段出现在多个位置”可以构成较强的克隆疑点；GS1 的表述仍是“may indicate suspicious activity”，而非自动证明假货。[GS1 Digital Signatures, §2](https://ref.gs1.org/guidelines/digital-signatures/)

### 3. 定位比较必须带不确定性

位置判定不应只比较一个经纬度点：

- 浏览器定位保存 `latitude`、`longitude`、`accuracy_m`、授权状态和服务端接收时间。
- IP 定位保存提供方、库版本/查询时间、国家/省/市、`accuracy_radius_km`、代理/VPN等质量特征；不能把城市中心点当作用户精确位置。MaxMind 要求展示坐标时同时展示精度半径，并明确坐标代表一个区域而不是精确位置。[MaxMind IP Geolocation API](https://www.maxmind.com/en/geoip-api-web-services)
- 若“观察位置的不确定范围”与“预期区域 + 业务容差”相交，则结果为 `uncertain`，不应触发确认式跨区告警。
- 消费者拒绝地理位置授权时主旅程仍应可用；系统降级到 IP 粗粒度信号，并降低风险置信度。

以上是基于 W3C 精度语义和 MaxMind 精度半径定义作出的产品推论，不是两个标准直接规定的跨区算法。

## 建议的数据与审计字段

为了让调查结论可解释、可纠正，每次观察至少保留：

- `code_id`、码生命周期状态快照、`observed_at`（服务端）；
- `location_source`：`browser`、`ip` 或 `none`；
- 浏览器位置及 `accuracy_m`，或 IP 地理数据及 `accuracy_radius_km`、数据版本；
- 来源 IP 的哈希/受控值、可信代理解析结果；
- 浏览器环境的受控风险标识（不得对运营人员呈现为“物理设备 ID”）；
- 当时生效的码段、经销商、预期区域和流向版本；
- 命中的规则、阈值版本、证据质量和风险级别；
- 调查结果：误报、确认窜货、继续观察，以及处理人、理由、附件和时间。

其中流向事件应保留 what、when、where、why 的业务语义，而不是只存一个当前位置；这与 GS1 EPCIS 的事件模型一致。[GS1 EPCIS 2.0.1, §7.3](https://ref.gs1.org/standards/epcis/2.0.1/)

## 对后续产品规划的决策建议

1. **锁定产品承诺**：本轮交付“轻量验真与风险提示”，不交付物理商品真伪鉴定。
2. **锁定状态机措辞**：首次、重复、异常都必须带“本系统记录/提示”的限定；只有平台生命周期状态可确定性展示。
3. **锁定跨区闭环**：系统自动产生带证据质量的线索，人工调查后才能标记“确认窜货”；单次跨区不自动处罚。
4. **锁定信号优先级**：可信流向记录和高质量授权定位高于 IP 粗定位；设备、IP、次数和速度只作组合信号。
5. **锁定不确定性模型**：浏览器 `accuracy_m`、IP `accuracy_radius_km`、定位来源和代理质量进入规则与 UI，不允许只存裸经纬度。
6. **锁定降级行为**：拒绝定位不阻断溯源和基础验真；跨区判断降为低置信度或信息不足。
7. **保留升级路径**：若未来需要更强防伪承诺，另立产品能力，引入数字签名与实例级物理安全特征绑定，而不是提高现有次数/地理规则阈值。
