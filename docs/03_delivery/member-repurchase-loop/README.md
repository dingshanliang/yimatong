# 会员复购闭环验收证据包

本证据包验证标准产品的内部闭环，不把 mock、HTTP 200 或页面截图当作真实微信能力。
固定业务链为 `REPURCHASE-BASE-001`，数据版本为 `yimatong-member-repurchase-v1`，首期积分关闭。

## 四层证据

| 层级       | 证明内容                                                             | 失败语义                              |
| ---------- | -------------------------------------------------------------------- | ------------------------------------- |
| 浏览器     | 从真实包装码进入，可匿名看溯源；明确同意后加入品牌会员并看到恢复编号 | `failed`                              |
| API        | 扫码令牌、同意回执、会员、券、商城事件及通知契约                     | `failed`                              |
| PostgreSQL | 同租户业务链、RLS、幂等事件、退款回冲、审计和事实型回滚保护          | `failed`                              |
| 外部       | 真实微信 AppID、订阅模板、支付、退款和对账                           | 未取得凭证时仅可为 `pending_external` |

场景与测试的机器可读映射见 `evidence-manifest.v1.json`。运行：

```bash
python3 scripts/verify_member_repurchase_evidence.py \
  --output artifacts/member-repurchase-evidence.json
```

报告只允许 `passed`、`failed`、`pending_external`。任一内部组失败时总体为 `failed`；内部全部通过但
真实微信门禁未退出时总体为 `pending_external`。发布回退采用应用版本回退并保留向前兼容数据库；
已产生会员、券、订单、退款或审计事实时，迁移降级必须被数据库预检阻断，不允许删事实回滚。

微信侧一次用户操作可以同时完成渠道授权和营销同意，但系统必须分别保存两份证据：渠道授权证明
微信允许本次发送，营销同意证明品牌可发送营销内容。这不会增加第二个前台步骤，也不能用其中一份
替代另一份。
