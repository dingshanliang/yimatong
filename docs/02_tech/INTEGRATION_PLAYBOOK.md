# 外部系统与电商权益集成方案

## 1. 集成原则

一码通不应假设所有主流电商都有开放、稳定、可随便调用的发券接口。现实情况是：有接口不等于有权限；能跳转领券不等于能 API 发券；能 API 发券不等于能拿到订单；能拿到订单不等于能匹配到扫码用户。

因此，一码通应把外部权益设计为“权益连接器”，按层级兼容不同平台。

## 2. 外部权益连接器分级

### L1 外部链接/口令配置

适合淘宝、京东、抖店、快手、有赞、微盟、自建商城、公众号文章、小程序页面等。

```text
客户在外部平台创建券/活动/商品页
→ 复制链接、口令、二维码或跳转路径
→ 配置到一码通权益中心
→ 消费者扫码点击
→ 跳外部平台领取或购买
→ 一码通记录点击归因
```

优点：最快落地。  
缺点：不一定知道是否领券、用券、成交。

### L2 外部券码池

客户从外部平台导出一批券码，导入一码通。一码通按规则一人一码发放。

```text
外部平台生成券码
→ 导入一码通券码池
→ 消费者扫码领取
→ 一码通分配唯一券码
→ 用户去外部渠道使用
→ 后续可手动导入核销/成交
```

优点：无需 API，也能实现唯一券码分发。  
缺点：核销和订单回流需要人工或批量导入。

### L3 API 发券

适合有赞、微盟、微信支付商家券、支付宝商家券、自建商城等更容易开放接口或由商家授权的平台。

```text
商家授权一码通
→ 一码通调用外部平台 API
→ 发券/查券/核销/查询订单
→ 写入权益与转化记录
```

约束：需要平台权限、商户授权、服务商资质、用户身份匹配。

### L4 订单回流与 GMV 归因

```text
外部平台订单 API / Webhook / 联盟回调 / 手动导入
→ 一码通根据手机号、unionid、券码、tracking_id、code_id 匹配
→ 计算扫码活动归因 GMV
```

优点：形成完整增长闭环。  
难点：平台权限和身份匹配。

## 3. 平台策略

| 平台 | 第一版策略 | 深度集成策略 |
|---|---|---|
| 有赞 | 链接 + 券码池 | API 发券、订单回流 |
| 微盟 | 链接 + 券码池 | API 发券、订单回流 |
| 微信支付商家券 | 先作为高级连接器 | 创建、发放、核销、对账 |
| 支付宝商家券 | 先作为高级连接器 | 创建、投放、领取、核销 |
| 淘宝/天猫 | 链接、口令、推广转链 | 看商家/开放平台权限 |
| 京东 | 链接、联盟/店铺活动 | 看商家/开放平台权限 |
| 抖店 | 抖音内跳转/链接 | 看小程序/电商插件权限 |
| 快手小店 | 跳转配置 | 后续按权限接入 |
| 自建商城 | 优先深度对接 | API 发券、订单回流、会员同步 |
| 企业微信 | 加企微、渠道活码、标签 | SCRM 数据回流视权限 |
| 公众号/小程序 | 跳转、订阅消息 | 用户授权、会员、积分对接 |

## 4. 与客户内部系统集成

### 4.1 批量导入优先

第一版优先支持：

- 产品导入。
- SKU 导入。
- 批次导入。
- 经销商导入。
- 码段分配导入。
- 外部成交导入。

### 4.2 API/Webhook 高级能力

后续支持：

- ERP 产品/批次同步。
- 进销存出库流向同步。
- CRM 客户同步。
- 会员系统积分同步。
- 商城订单回流。
- GTS/食链通追溯数据联动。

## 5. 与食链通/GTS 的关系

一码通可以独立使用，也可以与食链通/GTS 联动。建议文案：

```text
一码通可独立完成包装扫码增长闭环；对于已有食链通/GTS 的客户，可将更完整的追溯节点、检测报告、监管数据同步到一码通扫码页中，增强消费者信任与营销转化。
```

避免文案：

```text
客户必须先使用 GTS 才能使用一码通。
```
