# 安全、合规与风控

## 1. 安全目标

一码通的二维码会被印刷到真实包装上，属于长期在线入口。系统必须保证短链不容易被枚举，页面内容不可被随意篡改，权益发放不被批量刷取，消费者个人信息收集和营销触达有明确授权和退出机制。

## 2. 访问安全

| 能力       | 要求                                           |
| ---------- | ---------------------------------------------- |
| HTTPS      | 所有扫码页、后台、API 强制 HTTPS               |
| 短链防枚举 | public_id 使用随机/签名编码，不使用自增 ID     |
| 请求限流   | 按 IP、设备、码、租户、接口进行限流            |
| 防爬虫     | 高频访问、批量扫号、异常 UA 预警               |
| 幂等控制   | 领券、积分、核销、导入、发券必须支持幂等       |
| 域名安全   | 客户自有域名需验证所有权，配置 HTTPS 证书      |
| 文件安全   | 证书、报告、素材存储在对象存储，访问有权限控制 |

## 3. 内容安全与防篡改

- 页面发布采用版本管理。
- 线上版本锁定，修改必须新建草稿版本。
- 支持预览、发布、下线、回滚。
- 发布、下线、回滚均记录操作日志。
- 检测报告、资质证书、活动规则变更保留历史记录。
- 二维码不直接绑定静态文件，而绑定码 ID / 产品 / 批次 / 活动规则，由系统解析当前页面版本。

## 4. 个人信息与授权管理

消费者扫码看溯源可以免登录；领券、积分、留资、订阅消息、营销触达时需要按场景授权。

必须记录：

- 用户协议版本。
- 隐私政策版本。
- 授权类型。
- 授权目的。
- 授权时间。
- 授权页面版本。
- IP / UA / 来源。
- 撤回授权时间。

字段分级：

| 字段                | 等级                | 要求                               |
| ------------------- | ------------------- | ---------------------------------- |
| 匿名 ID             | 普通                | 可用于基础统计                     |
| 扫码行为            | 行为数据            | 合理告知                           |
| 手机号              | 个人信息            | 明示目的并授权，存储加密/脱敏      |
| 微信 openid/unionid | 个人信息            | 明示授权和用途                     |
| 地区                | 普通/个人信息视精度 | 尽量使用城市级，不强制精确定位     |
| 行踪轨迹/精确定位   | 敏感                | 第一版尽量不采集，若采集需单独授权 |
| 购买意向/表单       | 个人信息            | 明确字段用途、可撤回               |

外部权益连接器的凭证与 PII 边界：

- 连接器凭证（client_secret、access_token、refresh_token、token 有效期等）全部经
  AES-256-GCM 信封加密存于 `connectors.secrets_encrypted`；应用层
  `SENSITIVE_CONFIG_KEYS` 与数据库 CHECK 约束双重禁止明文落入公开 `config`。
- 外部 OAuth token 生命周期（有赞 7 天 access_token / 28 天单次 refresh_token；微盟
  client_credentials 7 天、无 refresh_token、临期重取）由适配器 `prepare` 钩子在
  发放/同步前维护：行级锁防并发双刷，独立租户上下文事务提交。
- 外部平台回调端点无 JWT，防线为 Redis IP 限流（fail-closed）→ 适配器签名验证
  （默认拒绝）→ 连接器身份限流 → PG 专用回调角色 + SQL 权威函数。
- 经连接器对外发放权益使用消费者 openid 或手机号时，必须先取得场景化隐私同意
  （现金 `wechat_cash_payout`、外部权益 `wechat_benefit_delivery`，consent purpose
  已随迁移 a34cfb8027f0 播种、公开授予端点可用），未同意走发放失败重试链，绝不
  静默使用；微盟以手机号桥接外部会员（customer/import 换 wid），手机号仅在该
  同意场景下解密出域，且隐私治理抑制（lead_contact_suppressed）视同不可用。

## 5. 营销触达合规

- 未经同意，不发送商业性短信、电话或消息。
- 用户同意接收商业信息时，必须提供明确、便捷的取消方式。
- 用户取消后，应立即停止对应触达。
- 企微/公众号/小程序订阅消息需遵守对应平台规则。
- 营销触达记录保留：内容、时间、渠道、授权依据、退订状态。

## 6. 活动规则与法律声明

每个活动至少配置：

- 活动时间。
- 参与条件。
- 领取限制。
- 权益有效期。
- 使用范围。
- 核销方式。
- 库存与预算。
- 隐私授权。
- 免责说明。
- 未成年人提示。
- 客服联系方式。

## 7. 活动风控规则

| 类型       | 示例                           |
| ---------- | ------------------------------ |
| 用户限制   | 每人限领 1 次，每日最多 3 次   |
| 手机号限制 | 同手机号每活动限领 1 次        |
| 设备限制   | 同设备短时间多次领取预警       |
| IP 限制    | 同 IP 高频请求限流             |
| 码限制     | 每个内码只能领奖一次           |
| 区域限制   | 非指定区域不可参与或仅预警     |
| 预算限制   | 活动总预算、每日预算、渠道预算 |
| 库存限制   | 权益库存耗尽后停止发放         |
| 时间限制   | 非活动期展示常规页             |

## 8. 轻量防伪表述边界

正确表述：

```text
一码通支持基于一物一码、首次扫码、重复扫码、区域异常和行为风控的轻量验真能力，帮助企业提升消费者信任，发现疑似假冒和窜货线索。
```

避免表述：

```text
二维码可以彻底防伪。
```

原因：普通二维码可以被拍照、复制、转发。真正更强的防伪需要外码/内码、刮开层、易碎标签、NFC、激光标、隐形码、数字水印等物理或复合技术配合。

## 9. 数据导出与审计

- 数据导出必须受权限控制。
- 包含个人信息的导出必须有导出原因和审计记录。
- 导出文件建议设置有效期。
- 平台、代运营、品牌方、区域品牌只能导出自己授权范围内数据。
- 经销商、门店、导购只能查看或导出自己的归因数据。
