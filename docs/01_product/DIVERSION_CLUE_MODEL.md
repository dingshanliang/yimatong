# 窜货线索证据与处置模型

状态：产品决策已确认  
确认日期：2026-07-26

## 1. 产品承诺

一码通根据渠道流向和扫码观察发现值得调查的跨区模式，帮助品牌方形成、调查和关闭窜货线索。

系统不因单次异地扫码自动认定窜货，不自动处罚渠道。确认窜货必须由授权人员结合业务佐证作出人工结论。

## 2. 三层风险对象

### 位置观察

每次扫码都可以记录位置事实，包括：

- 服务端观察时间；
- 位置来源：浏览器授权定位、IP 粗定位或无位置；
- 坐标、城市及对应精度或精度半径；
- 位置数据提供方和版本；
- 受控的网络及浏览环境风险特征。

位置观察不等于实际销售地点，也不直接说明流向异常。

### 跨区观察

位置观察与当时有效的预期区域存在明显偏离，但尚未达到正式调查门槛时，形成跨区观察。

以下情况只形成观察，不直接形成正式线索：

- 单次 IP 粗定位落在区域外；
- 定位精度范围与预期区域或容差相交；
- 消费者旅行、送礼、网购等情况尚未排除；
- 预期区域或流向资料缺失；
- 只有扫码位置，没有其他证据。

### 窜货线索

只有存在可靠流向基线，并且跨区观察达到证据门槛时，才形成正式窜货线索。

可支持升级的情形包括：

- 高质量授权定位明显在预期区域外；
- 相同渠道、批次或异常路径持续出现偏离；
- 多枚码在同一时间窗口集中偏离；
- 同一码在不可能通行的时间距离内出现高质量位置冲突；
- 观察与可信出库、调拨或渠道授权记录直接冲突。

## 3. 聚合单位

窜货线索按“一个可调查问题”创建，不按一次扫码创建。

一条线索可以关联：

- 一枚或多枚码；
- 一个或多个跨区观察；
- 一个码批次或多个明确相关的码批次；
- 同一经销商、异常路径和时间窗口。

后续出现相同模式时，应追加到原线索。单枚码存在不可能时间距离等强证据时，可以独立形成一条线索。

## 4. 处理进度与调查结论

处理进度和调查结论分别记录。

### 处理进度

| 进度     | 含义                                   |
| -------- | -------------------------------------- |
| 待核实   | 已形成正式线索，等待责任人接手         |
| 调查中   | 已有责任人开始核实和收集证据           |
| 已关闭   | 已记录调查结论并完成当前处置           |
| 重新打开 | 关闭后出现新观察或新证据，再次进入调查 |

### 调查结论

| 结论                | 含义                               |
| ------------------- | ---------------------------------- |
| 确认窜货            | 证据达到确认门槛                   |
| 合理调货 / 正常流通 | 存在可验证的正常业务解释           |
| 基础数据错误        | 流向、区域或渠道主数据有误         |
| 误报                | 风险信号不代表实际跨区流通问题     |
| 证据不足，继续观察  | 当前不足以定性，关闭调查但保留观察 |

“已处理”不是可接受的调查结论。

已关闭线索出现新证据时可以重新打开，但必须保留原结论和历史。

## 5. 确认窜货门槛

标记“确认窜货”必须同时具备：

1. 当时有效且可审计的经销商、码批次、预期区域和渠道流向；
2. 足够可靠的跨区观察；
3. 至少一项业务佐证：
   - 渠道确认；
   - 订单或物流记录；
   - 未授权销售凭证；
   - 现场调查材料；
4. 调查人员填写结论理由并上传或关联证据。

如果只有扫码异常，没有业务佐证，最高只能选择“证据不足，继续观察”，不得确认窜货或处罚渠道。

## 6. 自动动作边界

正式线索形成后，系统可以自动：

- 通知负责的品牌运营或渠道人员；
- 设置风险等级和处理时限；
- 汇总并持续追加相关观察；
- 高风险时建议暂停权益或冻结。

系统不能自动：

- 确认窜货；
- 冻结或作废码；
- 停用经销商或门店；
- 扣罚渠道；
- 向消费者宣称商品发生窜货。

营销防刷可以依据独立规则暂停可套利权益，但不能因为生成窜货线索就自动处罚渠道。

## 7. 角色权限

| 角色             | 查看             | 补充证据 | 调查与结论     | 关闭线索       |
| ---------------- | ---------------- | -------- | -------------- | -------------- |
| 品牌管理员       | 本租户全部       | 是       | 是             | 是             |
| 授权品牌风控运营 | 授权范围         | 是       | 是             | 是             |
| 经销商           | 仅与自身有关     | 是       | 否             | 否             |
| 代运营           | 经租户授权的客户 | 是       | 经授权         | 经授权         |
| 平台管理员       | 审计支持范围     | 是       | 仅审计支持流程 | 仅审计支持流程 |

经销商不能自行裁定涉及自己的线索为误报，也不能确认窜货或关闭线索。

## 8. 证据快照与审计

线索创建时必须保存不可被后续主数据覆盖的证据快照：

- 关联码、产品、SKU 和码批次；
- 当时生效的经销商、门店、预期区域和流向版本；
- 每个位置观察的来源、精度、时间及数据版本；
- 命中的规则、阈值版本、证据质量和风险等级；
- 聚合原因和时间窗口。

处置过程必须追加记录：

- 责任人和处理时限；
- 状态变化；
- 评论、附件和业务佐证；
- 调查结论、理由和处理动作；
- 操作人和时间；
- 重新打开的原因和新证据。

渠道区域或流向主数据后来发生变化时，历史线索不得静默重算或覆盖。系统可以发起重新评估或重新打开，并同时保留原始快照和新判断。

## 9. 规格与验收约束

后续规格必须验证：

1. 单次低质量异地扫码只形成位置或跨区观察，不直接形成正式线索。
2. 正式线索必须存在可靠流向基线并满足证据门槛。
3. 同一异常模式的多个观察可以聚合到一条线索。
4. 处理进度与调查结论分开保存和展示。
5. 没有业务佐证时不能选择确认窜货。
6. 正式线索不会自动冻结码、停用渠道或执行处罚。
7. 经销商能举证但不能裁定或关闭涉及自己的线索。
8. 关闭后出现新证据可以重新打开，且原结论不可丢失。
9. 主数据变化不能覆盖线索创建时的证据快照。
10. 真实浏览器、API 和数据库持久化结果能共同证明完整调查闭环。
