# 首个规格包：三线产品闭环

状态：产品边界与切片顺序已确认  
确认日期：2026-07-26  
下一阶段：`/to-spec`

## 1. 规格包目标

首个规格包以基准客户场景为产品模型，交付一套可重复运行、可独立验收的标准产品闭环：

1. 消费者扫码获得一致的产品溯源和轻量验真结果；
2. 品牌方获得可信的权益、留资、企微、跳转、订单和转化数据；
3. 品牌方能够基于可靠流向与位置观察调查渠道防窜线索；
4. 基准数据、多租户隔离、权限、审计和三层证据成为持续发布门禁。

本规格规划产品开发，不包含真实客户试点、商务上线或现场运营。

## 2. 权威产品契约

`/to-spec` 必须以以下已确认模型为业务权威：

- [轻量验真状态模型](VERIFICATION_STATE_MODEL.md)
- [增长转化事件与漏斗模型](GROWTH_CONVERSION_MODEL.md)
- [窜货线索证据与处置模型](DIVERSION_CLUE_MODEL.md)
- [基准数据与三线验收矩阵](BASELINE_ACCEPTANCE_MATRIX.md)

当现有 PRD、接口、数据库字段、页面或测试与上述模型冲突时，本规格包采用上述模型，并同步修订旧契约，不保留两套业务解释。

必须消除的旧语义包括：

- 已生成、已导出、已扫、异常不再作为码生命周期；
- 点击、入口展示和页面跳转不再作为确认转化；
- 单次区外扫码不再直接作为正式窜货线索；
- 页面模板不再维护独立于权威生产批次的溯源事实；
- 错误测试断言随业务契约修订，不以兼容错误行为为目标。

## 3. 规格结构

首个规格采用一份统一规格、四个纵向切片：

| 顺序 | 纵向切片       | 主要依赖                     | 用户可见结果                                         | 完成门禁                             |
| ---- | -------------- | ---------------------------- | ---------------------------------------------------- | ------------------------------------ |
| 1    | 基准底座       | 无                           | 品牌方能从干净环境建立产品、批次、码和可访问 H5      | 重建、构建、权限、权威数据和隔离通过 |
| 2    | 溯源与轻量验真 | 基准底座                     | 消费者获得正确溯源、首次/重复验证和状态结果          | 验真独立矩阵通过                     |
| 3    | 增长转化       | 基准底座、有效页面访问契约   | 消费者完成权益、留资、企微或跳转，品牌方看到可信结果 | 增长独立矩阵通过                     |
| 4    | 渠道防窜       | 基准底座、权威扫码与位置观察 | 品牌方和经销商完成线索调查与举证                     | 防窜独立矩阵通过                     |
| 5    | 三线联合门禁   | 四个切片                     | 标准产品状态可被证据证明                             | 全部共同及独立门禁通过               |

三条价值线共享码、产品、批次、身份和扫码事实，但分别开发、分别验收，不以总分相互补偿。

## 4. 切片一：基准底座

### 产品边界

基准底座只解决三条线共同依赖，不提前实现增长或防窜业务。

### Tracer bullets

1. **干净初始化**
   - 从干净环境创建基准租户和隔离对照租户；
   - 建立默认角色、权限和套餐基础；
   - 连续初始化两次无重复脏数据。

2. **权威产品与码数据**
   - 创建品牌、产品、SKU、生产批次、检测报告、资质证书和码批次；
   - 品牌管理员具备生成码所需权限；
   - 产品、生产批次、码批次和页面绑定关系可审计。

3. **可运行消费者入口**
   - Backend、Admin、H5 正常构建和启动；
   - 真实码可以从公开入口解析并打开 H5；
   - H5 与后台展示相同的权威产品和生产批次。

4. **隔离与证据基线**
   - 同名对照数据不能被跨租户访问；
   - 每个基准对象使用稳定业务标识；
   - 验收可以记录浏览器、API 和数据库三层证据。

### 必须修复的已知阻塞

- H5 当前构建或编译失败；
- 新租户默认权限缺少生成码能力；
- Demo 或基准种子存在类型导入失败；
- 页面配置与生产批次存在重复且可能冲突的数据来源。

### Release gate

任一已知阻塞未修复、基准数据无法连续重建或跨租户隔离失败，后续三条线不得标记通过。

## 5. 切片二：溯源与轻量验真

### Tracer bullets

1. **有效码首次验证**
   - 消费者扫码展示品牌、产品、SKU、权威生产批次、检测报告和资质；
   - 同一码全局只有第一条有效消费者验证被标记为首次验证。

2. **正常重复验证**
   - 展示首次验证时间和累计次数；
   - 不泄露其他消费者身份、位置、设备或网络信息。

3. **状态结果矩阵**
   - 未激活、冻结、作废、查无此码分别形成正确消费者结果；
   - 冻结可恢复，作废不可恢复。

4. **异常使用闭环**
   - 异常码保留真实溯源；
   - 展示审慎风险提示并暂停可套利权益；
   - 形成后台风险记录，但不自动判假、冻结或作废。

5. **人工处置与权限**
   - 授权人员可以冻结、解冻或作废；
   - 高风险动作有原因、二次确认和审计；
   - 未授权角色被拒绝。

### Release gate

[基准数据与三线验收矩阵](BASELINE_ACCEPTANCE_MATRIX.md)中的溯源与轻量验真场景必须全部通过。

## 6. 切片三：增长转化

### Tracer bullets

1. **有效访问与身份基线**
   - 记录有效页面访问、匿名访客和有依据的身份升级；
   - 排除无效状态、异常权益暂停、机器人和测试流量。

2. **站内确认结果**
   - 权益领取成功且重复请求不重复发放；
   - 留资在明确授权后保存，敏感数据与授权记录正确。

3. **外部入口与企微确认**
   - 企微和商城入口点击只形成意向事件；
   - 只有成功处理企业微信官方添加回调才形成确认转化。

4. **订单与净 GMV**
   - 标准订单导入通过来源、字段、金额和重复校验；
   - 取消和退款回冲净 GMV，并保留审计。

5. **漏斗与归因**
   - 主漏斗以有效页面访问去重访客为分母；
   - 权益、留资和企微默认使用 7 天归因窗口；
   - 订单和 GMV 默认使用 30 天归因窗口；
   - 窗口内采用最后一次有效入口并保存归因快照；
   - 访问人群漏斗与经营日报分开。

### Release gate

[基准数据与三线验收矩阵](BASELINE_ACCEPTANCE_MATRIX.md)中的增长转化场景必须全部通过。

## 7. 切片四：渠道防窜

### Tracer bullets

1. **渠道流向基线**
   - 建立经销商、码批次、授权区域和有效期；
   - 渠道流向可版本化并可形成历史快照。

2. **位置与跨区观察**
   - 保存位置来源、精度、时间和数据版本；
   - 区内扫码保持正常；
   - 单次低质量区外扫码只形成跨区观察。

3. **线索聚合**
   - 持续偏离按经销商、码批次、异常路径和时间窗口聚合；
   - 强证据单码可以独立成线索。

4. **调查与举证**
   - 品牌运营调查并管理处理进度；
   - 经销商只查看与自身有关的线索并补充业务证据；
   - 经销商不能裁定或关闭线索。

5. **结论与重新打开**
   - 支持证据不足、误报、正常调货、基础数据错误和确认窜货；
   - 确认窜货必须具备业务佐证和人工理由；
   - 新证据可以重新打开，原结论保持不变。

6. **审计与自动动作边界**
   - 线索保存不可覆盖的证据快照；
   - 系统可以通知、聚合和建议；
   - 系统不自动冻结码、停用渠道、扣罚或确认窜货。

### Release gate

[基准数据与三线验收矩阵](BASELINE_ACCEPTANCE_MATRIX.md)中的渠道防窜场景必须全部通过。

## 8. 历史数据与迁移

采用“安全迁移、不伪造历史”：

- 数据库结构变更必须提供可回滚迁移；
- 能明确映射的码、批次、扫码和渠道数据正常迁移；
- 页面模板中的重复产品或批次字段不再作为权威来源；
- 无法可靠还原的首次验证、归因或窜货证据标记为历史未归因，或不进入新指标；
- 不根据弱信号回填验真、转化或窜货结论；
- Demo 和基准数据直接重建，不保留旧 Demo 兼容逻辑；
- 当前规格不建设面向旧客户系统的通用迁移工具。

## 9. 渐进交付规则

- 每个 tracer bullet 在自身浏览器、API、持久化、权限和相关测试通过后可以合并；
- 每条价值线完成后可以独立标记为该线通过；
- 用户可见但尚未完整的入口必须通过租户级能力开关隐藏；
- 能力开关不能跳过已经纳入规格的硬门禁；
- 只有共享底座、三条价值线、共同门禁和外部集成烟测全部通过，才能标记标准产品完成。

## 10. 首个规格包不包含

- 既有码接管、客户域名/CNAME 和旧码迁移；
- 外码/内码双码、产线喷码和完整印刷协作流程；
- 自建交易、支付、物流、售后和复杂 CRM/ERP；
- 电商平台专用订单连接器，首包只提供标准订单导入；
- 积分商城、抽奖、红包和高级会员体系；
- AI 配置、区域品牌高级能力、白标、多语言和私有化；
- 客户上线清单、试点确认和 7/14/30 天复盘；
- 与三条基准旅程无关的普通 P2 UI 优化。

这些能力不进入当前验收，也不阻塞首个规格包完成。
