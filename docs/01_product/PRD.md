# 一码通 PRD

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | 一码通 |
| 产品定位 | 独立闭环的包装扫码增长 SaaS |
| 版本 | v1 完整规划版 |
| 交付形态 | 公有云多租户 SaaS + 代运营配置服务，预留专属租户/私有化能力 |
| 首要行业 | 食品、农产品品牌方 |
| 扩展行业 | 消费品、区域品牌、协会、渠道供应链、园区/政府产业项目 |
| 与 GTS 关系 | 可联动，但不依赖 |

## 2. 背景与机会

产品包装上的二维码正在从“静态信息入口”变成“产品数字身份入口”。国际标准层面，GS1 Sunrise 2027 推动零售行业从一维 UPC 条码向二维码等二维条码过渡，强调更丰富的数据、透明度、追溯和消费者信息连接。食品包装 QR 码在追溯、质量评价、防伪和营销方面也已经有明确应用价值。

但国内食品/农产品品牌方普遍存在一个断层：

- 做溯源的人关注批次、证书、监管、产地，但不懂私域和复购。
- 做电商和私域的人关注转化、裂变、GMV，但不懂包装、批次、一物一码和渠道流向。
- 二维码工具能生成码，但无法管理码生命周期、印刷落地、验真、防窜和转化归因。
- 食品/农产品客户运营能力弱，需要“产品化 SaaS + 代运营交付”而不是纯自助工具。

一码通的机会在于：把包装码作为实体商品的数字入口，把轻量溯源、营销权益、私域承接、用户画像、渠道风控和区域品牌管理组合成一个独立闭环产品。

## 3. 产品目标

### 3.1 商业目标

1. 将包装二维码从成本中心转化为增长入口。
2. 帮助品牌方沉淀消费者资产，提升复购和私域转化。
3. 为区域公用品牌/协会提供成员企业数字化管理工具。
4. 建立可标准化售卖的 SaaS 产品，而不是项目制系统。
5. 通过代配置、代运营、印刷/贴标/喷码对接服务提高客户落地成功率。

### 3.2 用户目标

消费者扫码后可以快速获得可信产品信息、领取权益、加入私域或跳转购买。品牌方可以低成本配置产品页面、批量生成或接管二维码、追踪扫码转化和渠道异常。代运营人员可以标准化完成资料收集、页面配置、活动上线、数据复盘。

### 3.3 不做什么

- 不做重型供应链溯源系统。
- 不做完整电商商城、支付、物流、售后。
- 不把普通二维码包装成绝对防伪能力。
- 不默认做现金红包和资金结算。
- 不默认要求客户先使用 GTS。

## 5. 核心场景

### 场景 1：新包装一物一码

品牌方创建产品、SKU、批次和活动，平台生成一物一码码包。码包可用于标签打印、可变数据印刷或产线喷码。码段经激活后，消费者扫码进入品牌 H5 页面。

关键需求：

- 支持批量生成唯一 HTTPS 二维码。
- 支持批次码、一物一码、外码/内码双码。
- 支持码包导出、印刷状态、激活、作废。
- 支持每个码绑定产品、SKU、批次、经销商、区域、活动。

### 场景 2：既有码接管

客户已有防伪码、溯源码、公众号二维码、商城二维码或旧包装固定链接。一码通通过域名解析、CNAME、中转跳转、批量导入旧码、重新贴码等方式接管扫码后体验。

关键需求：

- 支持客户自有域名或原域名接管。
- 支持旧码编号、产品、批次、渠道批量导入。
- 支持无法技术接管时给出迁移方案。
- 支持既有码与新活动页面绑定。

### 场景 3：扫码信任页 + 营销转化

消费者用微信扫一扫、手机相机、支付宝扫一扫或浏览器扫码，打开通用 H5 页面。页面展示品牌、产品、产地、批次、检测报告、资质证书，同时引导领券、加企微、关注公众号、跳小程序、跳电商店铺或提交表单。

关键需求：

- 二维码默认承载 HTTPS 链接，不强制小程序码。
- H5 页面根据扫码环境做承接分流。
- 溯源展示免登录。
- 权益领取、积分、留资、订阅消息时按场景授权。

### 场景 4：轻量验真与防复制预警

如果同一码首次被扫，系统提示首次验证；如果同一码被频繁多地扫码，系统提示消费者谨慎核对，并在后台产生疑似复制码预警。

关键需求：

- 每个最小销售包装一个唯一身份码。
- 支持首次扫码记录。
- 支持重复扫码提醒。
- 支持短时间多地扫码预警。
- 支持风险冻结和作废。
- 支持外码 + 内码双码模式：外码做展示引流，内码做验真、领奖、积分。

### 场景 5：轻量防窜货

码段分配给经销商、区域、门店或渠道。系统将实际扫码地区与预期销售区域比对，发现跨区扫码、异常高频扫码和渠道流向异常。

关键需求：

- 支持经销商、区域、门店主数据。
- 支持码段/码批次分配。
- 支持出库流向绑定。
- 支持扫码地与预期销售区域比对。
- 支持疑似窜货看板。

### 场景 6：区域公用品牌/协会管理

区域品牌或协会开通总账号，下挂多个成员企业。上级组织可以统一品牌背书、模板、码规则、授权产品和汇总看板；成员企业独立运营自己的产品和活动。

关键需求：

- 支持上级组织与成员企业关系。
- 支持统一模板、统一品牌背书、统一码规则。
- 支持授权产品管理。
- 支持成员企业独立配置活动。
- 支持区域品牌汇总看板。

### 场景 7：代运营配置与客户成功

平台或服务商帮客户完成资料收集、页面配置、活动策划、码包生成、印刷对接、上线检查和数据复盘。

关键需求：

- 支持代运营工作台。
- 支持客户初始化向导。
- 支持任务流：资料收集、页面配置、活动配置、码策略配置、上线检查、复盘。
- 支持客户健康度：低扫码、活动到期、码量不足、异常扫码。

## 7. 消费者端体验要求

### 7.1 扫码方式

第一版不应假设用户必须使用小程序。二维码默认是 HTTPS 链接，可以被微信扫一扫、手机相机、支付宝扫一扫、浏览器、抖音/快手扫一扫等打开。小程序码作为增强入口，而不是唯一入口。

### 7.2 登录与授权

- 溯源展示免登录。
- 领券、积分、抽奖、留资、订阅消息、营销触达时按场景要求授权。
- 授权前必须明确说明目的、范围、使用方式和退出机制。

### 7.3 页面模块

标准模块包括：

- 顶部品牌与产品卡片
- 首扫/验真状态
- 轻量溯源信息
- 产地与批次
- 检测报告与资质证书
- 视频/图文故事
- 优惠券/权益
- 积分与会员
- 私域入口：企微、公众号、小程序
- 电商店铺跳转
- 留资表单
- 活动规则与隐私授权
- 异常提示与客服入口

## 8. 关键指标

### 8.1 增长指标

| 指标 | 定义 |
|---|---|
| 扫码率 | 扫码人数 / 出货包装数或激活码数 |
| 独立扫码人数 | 去重消费者数 |
| 页面转化率 | 核心按钮点击 / 页面访问 |
| 领券率 | 领券人数 / 扫码人数 |
| 加私域率 | 加企微/公众号/社群人数 / 扫码人数 |
| 留资率 | 提交表单人数 / 扫码人数 |
| 复购跳转率 | 商城跳转人数 / 扫码人数 |
| GMV 归因 | 可匹配订单金额 / 扫码或活动来源 |

### 8.2 风控指标

| 指标 | 定义 |
|---|---|
| 重复扫码码数 | 超过设定次数的码数量 |
| 多地扫码码数 | 短时间跨多个城市扫码的码数量 |
| 跨区扫码率 | 非预期销售区域扫码数 / 总扫码数 |
| 异常领券率 | 被风控拦截或预警的领取行为占比 |
| 疑似复制码 | 同码多地、高频、异设备分布异常 |

### 8.3 运营指标

| 指标 | 定义 |
|---|---|
| 首个活动上线时长 | 从客户开通到首个活动发布 |
| 客户活跃度 | 近 30 天登录、配置、扫码、活动数 |
| 客户健康度 | 扫码、转化、到期、码量、异常综合评分 |
| 续费率 | 到期客户续费比例 |
| 增购率 | 码量包、扫码量包、服务包增购比例 |

## 9. 验收标准

### 9.1 核心闭环验收

- 能开通一个品牌方租户。
- 能配置产品、SKU、批次、检测报告和证书。
- 能生成一批一物一码，并导出码包。
- 能将码绑定产品、批次、页面和活动。
- 消费者扫码能打开 H5 页面。
- 页面能展示轻量溯源内容。
- 用户能领券、提交表单、点击企微/公众号/小程序/商城入口。
- 后台能看到扫码、领券、留资、跳转数据。
- 重复扫码能被记录并触发提示。
- 页面能草稿、预览、发布、下线。

### 9.2 SaaS 验收

- 不同租户数据隔离。
- 平台、代运营、品牌方、经销商、门店、印刷协作方权限不同。
- 套餐、额度、到期时间可配置。
- 码量、扫码量超额有提醒。

### 9.3 安全与合规验收

- 全站 HTTPS。
- 短链不可被简单枚举。
- 权益领取有频次限制。
- 留资和营销触达有授权记录。
- 消费者可查看隐私政策、活动规则和退订/撤回路径。
- 操作日志、发布记录、导出记录可追踪。

## 10. 风险与约束

| 风险 | 说明 | 应对 |
|---|---|---|
| 扫码率低 | 包装位置、引导文案、权益吸引力不足 | 提供包装引导语模板、首扫礼、活动复盘 |
| 客户不会配置 | 食品/农产品企业运营能力弱 | SaaS + 代配置 + 行业模板 + AI 辅助 |
| 防伪被误解 | 普通二维码不能绝对防伪 | 明确“轻量验真”，高价值产品推荐内外码 |
| 外部电商接口复杂 | 主流平台权限不统一 | 权益连接器分 L1-L4，先链接/券码池，再 API |
| 数据合规风险 | 收集手机号、微信、留资、行为数据 | 授权记录、字段分级、退订、导出权限 |
| 版本范围过大 | 完整规划能力多 | 研发分三阶段，核心闭环先上线 |
