# 增长转化事件与漏斗模型

状态：产品决策已确认  
确认日期：2026-07-26

## 1. 产品承诺

一码通把消费者扫码后的兴趣行为和可证明的业务结果分别记录，帮助品牌方判断“有多少人产生兴趣”以及“有多少人完成结果”。

增长分析不把点击包装成确认转化，不自建交易。商城订单和 GMV 只有获得可信外部回传后，才能作为确认结果。

## 2. 两层事件模型

### 意向事件

意向事件表示消费者浏览或点击了增长入口，但不证明后续结果已经发生。

| 业务事件     | 记账条件                                                      | 是否确认转化 |
| ------------ | ------------------------------------------------------------- | ------------ |
| 有效页面访问 | H5 成功加载，码可正常参与活动，流量未被识别为机器人或测试流量 | 否           |
| 权益入口点击 | 消费者主动点击领取入口                                        | 否           |
| 留资入口点击 | 消费者主动进入留资流程                                        | 否           |
| 企微入口点击 | 消费者点击企微入口或展示添加二维码                            | 否           |
| 商城跳转     | 产品成功执行外部商城跳转                                      | 否           |

原始扫码、解析请求和页面请求可以作为技术及风控诊断数据，但不自动构成有效页面访问。

### 确认结果

确认结果只有在权威业务结果成功落库或可信外部回传通过验证后记账。

| 业务结果     | 权威记账时点                                                                     | 去重依据                                   |
| ------------ | -------------------------------------------------------------------------------- | ------------------------------------------ |
| 权益领取成功 | 领取记录成功创建                                                                 | 活动、权益、消费者及业务幂等键             |
| 留资成功     | 表单通过校验并成功保存                                                           | 表单、消费者及业务幂等键                   |
| 确认添加企微 | 验签、解密并幂等处理企业微信 `change_external_contact/add_external_contact` 回调 | 连接器作用域、客户与成员关系、回调传输指纹 |
| 确认订单     | 可信订单成功回传或导入，并通过归因匹配                                           | 外部数据源与外部订单号                     |
| 确认 GMV     | 已确认订单的有效金额，扣除取消和退款回冲                                         | 外部数据源、订单及金额变更记录             |

按钮点击、请求发起、商城跳转成功和前端成功提示不能替代确认结果。重复请求或重复回调只记一次。

## 3. 漏斗与分母

后台分开展示：

1. **意向漏斗**：有效页面访问 → 权益、留资、企微或商城入口点击；
2. **确认结果漏斗**：有效页面访问 → 权益领取、留资、确认添加企微或确认订单；
3. **经营结果**：确认结果数量、确认订单和净 GMV。

主转化率统一以选定范围内的“有效页面访问去重访客数”为分母。每一步同时展示相邻步骤转化率，用于定位流失位置。

原始扫码次数单独展示为诊断指标，不作为增长主转化率分母，避免重复验证和异常扫码放大分母。

## 4. 有效页面访问

同时满足以下条件才进入增长漏斗：

- 消费者 H5 成功加载；
- 码处于可以正常参与活动的有效状态；
- 本次访问没有因异常使用信号暂停权益；
- 流量未被识别为机器人、自动化测试或内部测试。

以下情况只进入扫码、质量或风控数据，不进入增长漏斗：

- 查无此码、未激活、冻结或作废；
- 页面加载失败；
- 因异常使用信号暂停权益；
- 已识别的机器人或测试流量。

## 5. 访客身份与去重

漏斗按当前最可信的稳定身份去重：

1. 未登录消费者使用匿名访客 ID；
2. 权益领取或留资后使用系统消费者 ID；
3. 企微确认结果使用连接器作用域内的外部联系人 ID；
4. 订单使用可信外部客户或订单身份，并保留其数据源作用域。

身份升级时可以建立有依据的关联，但必须保留原始事件与关联依据。跨设备匿名访问不强行合并，IP、设备特征和位置不能单独作为合并消费者身份的依据。

## 6. 入口归因

确认结果采用“归因窗口内最后一次有效入口”：

| 结果类型                     | 默认归因窗口 |
| ---------------------------- | ------------ |
| 权益领取、留资、确认添加企微 | 7 天         |
| 外部订单与 GMV               | 30 天        |

归因窗口为租户级可配置项。超出窗口的结果计入经营结果总量，但不强行归因到具体活动、页面、码批次或渠道。

归因完成时必须保存不可被后续配置覆盖的快照：

- 租户与消费者身份作用域；
- 活动及活动版本；
- 页面及页面版本；
- 产品、SKU、生产批次和码批次；
- 渠道、入口及企业微信 `state` 等入口标识；
- 归因规则、窗口和记账时间。

企业微信 `state` 只用于活动或入口级归因，不能单独证明某次匿名 H5 访问者就是后来添加的外部联系人。

## 7. 外部结果边界

外部订单和 GMV只有以下来源可以计入确认结果：

- 已认证的平台接口；
- 验签通过的 Webhook；
- 按标准模板导入并通过字段、身份、金额和重复性校验的数据。

人工填写的汇总金额只能标记为参考数据，不能作为确认转化。

订单取消和退款必须回冲净 GMV，保留原值、变更值、原因、来源和处理时间。历史归因关系不因退款而删除。

后台必须区分：

- 尚未连接或尚未回传数据；
- 已连接并完成同步，但结果为零；
- 数据同步异常或覆盖范围不完整。

每项外部结果需展示数据来源、覆盖范围和最后同步时间。

## 8. 时间报表

后台同时提供两种时间视图：

### 访问人群漏斗

以选定期间内产生有效页面访问的去重访客为一个人群，继续观察其在归因窗口内产生的确认结果。归因窗口结束前标记为“持续回收中”，窗口结束后才视为最终漏斗。

### 经营日报

按权益领取、留资、企微确认、订单和金额实际发生时间统计当天结果，用于运营跟进和财务观察。

两种视图不得共用一个未标注口径的“转化率”。

## 9. 规格与验收约束

后续规格必须验证：

1. 商城跳转和企微入口点击只进入意向漏斗，不计入确认转化。
2. 权益、留资、企微和订单只有在权威记账时点成功后才生成确认结果。
3. 重复请求、重复回调和重复订单导入不会重复记账。
4. 主漏斗以有效页面访问去重访客为分母，原始扫码次数单独展示。
5. 无效、不可参与、加载失败、异常暂停及机器人或测试访问不进入增长漏斗。
6. 匿名访客身份升级有可审计依据，不会仅凭 IP、设备或位置合并。
7. 窗口内按最后一次有效入口归因，窗口外结果保持未归因。
8. 归因快照不受后续活动、页面、产品或渠道配置变化影响。
9. 未接入外部数据、结果为零和同步异常在后台呈现为不同状态。
10. 退款和取消正确回冲净 GMV，同时保留完整审计记录。
11. 访问人群漏斗与经营日报使用各自明确的时间口径。
12. 真实浏览器、API 和数据库持久化结果能共同证明从有效访问到确认结果的完整闭环。
