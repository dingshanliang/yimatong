## Critical Findings

### C-1: list_roles 和 list_permissions 缺少 RBAC
- **Dimension:** 安全性
- **File:** `backend/app/api/v1/roles.py:29-44, 70-77`
- **Description:** `list_roles` 和 `list_permissions` 端点仅依赖 `get_current_tenant`，任何认证用户都能列出全部角色和权限。角色/权限信息可用于权限提升攻击。
- **Fix:** 添加 `Depends(require_role("admin", "operator"))`。

### C-2: db.get() 绕过 tenant_id 过滤
- **Dimension:** 安全性
- **File:** `backend/app/api/v1/roles.py:108, 111, 130`
- **Description:** 使用 `db.get(Role, role_id)` 直接按主键查找，再手动检查 `tenant_id`。应使用带 tenant_id 的 select 查询。
- **Fix:** 改为 `select(Role).where(Role.id == role_id, Role.tenant_id == tenant_id)`。

## High Findings

### H-1: 缺少角色更新和权限解除分配端点
- **Dimension:** 功能完整性
- **File:** `backend/app/api/v1/roles.py`（缺失）
- **Description:** 无法更新角色名称/描述（PATCH），无法解除角色-权限分配（DELETE permission from role）。
- **Fix:** 添加 `PATCH /roles/{role_id}` 和 `DELETE /roles/{role_id}/permissions/{permission_id}`。

### H-2: 缺少测试
- **Dimension:** 测试覆盖
- **File:** `backend/tests/`（缺失）
- **Description:** 角色模块无任何测试覆盖。
- **Fix:** 添加 CRUD + RBAC + 边界测试。

### H-3: Schema 定义在 API 文件内
- **Dimension:** API规范
- **File:** `backend/app/api/v1/roles.py:19-26`
- **Description:** Pydantic schema 内联在 API 文件中，违反四层架构。应提取到 `schemas/role.py`。
- **Fix:** 创建 `schemas/role.py`，导入使用。

### H-4: 无 response_model 声明
- **Dimension:** API规范
- **File:** `backend/app/api/v1/roles.py`（所有端点）
- **Description:** 所有端点未声明 `response_model`，FastAPI 无法自动验证响应和生成 OpenAPI 文档。
- **Fix:** 创建 RoleRead/PermissionRead schema 并设为 response_model。
