## High Findings

### H-1: mark-printing 和 mark-delivered 端点缺少 RBAC 权限检查
- **Dimension:** 安全性
- **File:** `backend/app/api/v1/code_batches.py:259-288`
- **Description:** `mark_printing_endpoint` 和 `mark_delivered_endpoint` 没有权限依赖（`require_permission`），可能被未授权用户调用。其他状态变更端点（activate/freeze/void）都正确使用了 `require_permission("code:manage")`。
- **Fix:** 添加 `_ = Depends(require_permission("code:manage"))` 到两个端点。

### H-2: 服务层直接使用 HTTPException
- **Dimension:** 代码质量
- **File:** `backend/app/services/code.py:410,430`
- **Description:** `revoke_code_item` 和 `bind_code_item` 函数直接 `from fastapi import HTTPException` 并抛出，违反分层架构原则。其他函数已改用 `ValueError`/`ConflictError`/`NotFoundError` 等领域异常。
- **Fix:** 替换为领域异常（`NotFoundError`、`BadRequestError`），由 API 层捕获转换。

### H-3: code_batches 缺少 tenant_id + batch_code 唯一约束
- **Dimension:** 数据模型
- **File:** `backend/app/models/code.py:69`
- **Description:** `code_batches` 表有复合索引 `ix_code_batches_tenant_batch` 但不是唯一索引，可能导致同一租户下重复批次号。服务层有应用层检查，但缺数据库级保障。
- **Fix:** 将 `Index` 改为 `UniqueConstraint("tenant_id", "batch_code", name="uq_code_batches_tenant_batch_code")`。

### H-4: 并发状态转换缺少锁机制
- **Dimension:** 性能
- **File:** `backend/app/services/code.py:331-530`
- **Description:** activate/freeze/void 等批量状态变更操作没有使用 `SELECT FOR UPDATE` 或乐观锁。并发请求可能导致同一批次被多次激活或状态不一致。
- **Fix:** 在状态变更前使用 `SELECT FOR UPDATE` 锁定批次行，或添加 `version` 字段实现乐观锁。

### H-5: 码生成数量无上限限制
- **Dimension:** 安全性
- **File:** `backend/app/api/v1/code_batches.py:42`（CodeBatchCreateRequest）
- **Description:** `quantity` 字段仅验证 `ge=1` 但无 `le` 上限，理论上可请求生成数百万码，导致数据库和内存压力。
- **Fix:** 添加 `quantity: int = Field(ge=1, le=100000)` 限制最大生成量。

## Medium Findings

### M-1: API 层包含业务逻辑（配额检查）
- **Dimension:** 架构
- **File:** `backend/app/api/v1/code_batches.py:99-123`
- **Description:** `create_code_batch_endpoint` 中直接进行配额检查 (`check_quota_for_tenant`)，应下沉至服务层。
- **Fix:** 将配额检查移入 `create_code_batch` 服务函数。

### M-2: 重复的缓存清理逻辑
- **Dimension:** 代码质量
- **File:** `backend/app/services/code.py:418,475,495`
- **Description:** `revoke_code_item`、`freeze_batch`、`void_batch` 等函数都有相似的缓存清理代码模式。
- **Fix:** 提取为 `_invalidate_batch_and_items_cache(db, batch_id)` 辅助函数。

### M-3: 导出接口使用 POST 而非 GET
- **Dimension:** API规范
- **File:** `backend/app/api/v1/code_batches.py:182`
- **Description:** 导出端点使用 `POST /{batch_id}/export`，RESTful 规范建议使用 GET 方法。但考虑到 POST 允许请求体参数（如导出选项），此设计可接受。
- **Fix:** 保持 POST（因导出可能需要复杂参数），但添加注释说明设计理由。

### M-4: 部分错误响应未使用 ErrorDetail 格式
- **Dimension:** API规范
- **File:** `backend/app/api/v1/code_batches.py:122,177,195`
- **Description:** 多处直接 `raise HTTPException(status_code=400, detail=str(exc))`，未使用统一的 `ErrorDetail` schema。
- **Fix:** 使用全局异常处理器（`core/exceptions.py` 已定义）统一格式。

### M-5: 码项管理前端页面缺失
- **Dimension:** 前后端一致性
- **File:** `frontend/apps/admin/src/app/(dashboard)/codes/`
- **Description:** 后端提供了完整的码项 CRUD API（列表、详情、吊销、绑定、pair 查询），但前端缺少码项级别的管理界面。
- **Fix:** 在码批次详情页添加码项 Tab，或创建独立的码项管理页面。

### M-6: 批次统计查询无分页保护
- **Dimension:** 性能
- **File:** `backend/app/services/code.py:250-291`
- **Description:** `get_code_batch` 中的状态统计查询（按状态分组计数）在码项数量极大时可能慢。虽然已有索引，但缺少查询超时保护。
- **Fix:** 添加 `LIMIT` 或使用 `EXPLAIN ANALYZE` 验证查询计划，确保索引命中。

### M-7: Excel 导入文件大小未限制
- **Dimension:** 安全性
- **File:** `backend/app/services/import_service.py`
- **Description:** 导入服务未限制上传文件大小，大文件可能导致内存溢出。
- **Fix:** 添加文件大小检查（如 `len(file_content) > 10 * 1024 * 1024` 则拒绝）。

### M-8: 缺少批量操作功能
- **Dimension:** 功能完整性
- **File:** `frontend/apps/admin/src/app/(dashboard)/codes/page.tsx`
- **Description:** 无法批量激活、吊销、冻结码项，影响运营效率。
- **Fix:** 添加批量操作按钮，支持多选后批量处理状态变更。

## Low Findings

### L-1: 缺少码批次复制功能
- **Dimension:** 功能完整性
- **File:** `backend/app/services/code.py`
- **Description:** 无法快速复制已存在的码批次配置创建新批次。
- **Fix:** 添加 `POST /code-batches/{id}/copy` 接口。

### L-2: 批量缓存失效效率低
- **Dimension:** 性能
- **File:** `backend/app/services/code.py:383-400`
- **Description:** `_invalidate_batch_cache` 逐条清除缓存，大批量操作时效率低。
- **Fix:** 使用 Redis `SCAN` + `DEL` 模式或 Pipeline 批量删除。

### L-3: 缺少码项过期机制
- **Dimension:** 用户体验
- **File:** `backend/app/models/code.py`
- **Description:** 码项缺少 `expired_at` 字段和自动过期处理逻辑。
- **Fix:** 评估是否需要过期机制（取决于业务需求），如需要则添加字段和定时任务。

### L-4: 导入模板说明不够详细
- **Dimension:** 用户体验
- **File:** `frontend/apps/admin/src/app/(dashboard)/imports/page.tsx`
- **Description:** 模板下载缺少详细的使用说明。
- **Fix:** 在模板文件中添加说明 Sheet，提供详细的填写指南。
