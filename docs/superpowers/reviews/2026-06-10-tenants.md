## High Findings

### H-1: /me PATCH 端点允许普通用户修改敏感字段
- **Dimension:** 安全性
- **File:** `backend/app/api/v1/tenants.py:180-202`
- **Description:** `update_current_tenant_endpoint` 使用完整的 `TenantUpdate` schema，允许普通租户用户修改 `plan_expires_at`、`quota`、`tenant_type`、`compliance_settings` 等仅 platform_admin 应该修改的字段。
- **Fix:** 创建 `TenantUpdateSelf` schema，限制 /me 端点只能修改 `name`、`industry`、`notes`、`categories`、`onboarding_progress`、`enabled_features`。

### H-2: Tenant 表缺少 status/plan/tenant_type 索引
- **Dimension:** 数据模型 / 性能
- **File:** `backend/app/models/tenant.py:53-58`
- **Description:** `list_tenants` 查询中按 `status` 过滤（`Tenant.status != "terminated"`），搜索按 `name` ILIKE，但 `status`、`plan`、`tenant_type` 字段没有索引。当租户数量增长时，查询性能会严重退化。
- **Fix:** 在迁移中添加 `idx_tenant_status`、`idx_tenant_plan`、`idx_tenant_type` 索引。

### H-3: create_tenant 中 4 次 flush 影响性能
- **Dimension:** 性能
- **File:** `backend/app/services/tenant.py:50-93`
- **Description:** `create_tenant` 函数依次 flush tenant → org → account → template，每次 flush 都是一次数据库往返。可以合并为更少的 flush。
- **Fix:** 考虑在所有 `db.add()` 之后只做一次 flush，或使用 batch 操作。

### H-4: 列表搜索缺少 plan/tenant_type/status 过滤
- **Dimension:** 功能完整性
- **File:** `backend/app/api/v1/tenants.py:73-101`
- **Description:** `list_tenants_endpoint` 仅支持按名称搜索（`q` 参数），缺少按 `plan`、`tenant_type`、`status` 的过滤参数。对于平台管理员来说，多维过滤是刚需。
- **Fix:** 添加 `plan`、`tenant_type`、`status` 查询参数，在查询中添加对应过滤条件。

### H-5: 缺少租户暂停/恢复功能
- **Dimension:** 功能完整性
- **File:** `backend/app/api/v1/tenants.py`
- **Description:** 仅有 `soft_delete_tenant`（terminated），缺少 `suspend`/`resume` 操作。实际运营中需要暂停和恢复租户（如欠费暂停、续费恢复）。
- **Fix:** 添加 `PATCH /{tenant_id}/suspend` 和 `PATCH /{tenant_id}/resume` 端点。

### H-6: /me 端点缺少审计日志
- **Dimension:** 安全性
- **File:** `backend/app/api/v1/tenants.py:46-64,116-139,142-150,180-202`
- **Description:** platform_admin 和普通租户用户的租户变更操作（创建、更新、删除）都没有审计日志。对比 auth 模块的密码重置有审计日志。
- **Fix:** 在 create_tenant、update_tenant、soft_delete_tenant 中添加审计日志。

### H-7: admin_password 缺少强度验证
- **Dimension:** 安全性
- **File:** `backend/app/schemas/tenant.py:21`
- **Description:** `TenantCreate.admin_password` 只有 `min_length=8`，没有调用 `validate_password_strength` 验证字母+数字要求。
- **Fix:** 添加 `@field_validator("admin_password")` 调用 `validate_password_strength`。

### H-8: 安全边界测试缺失
- **Dimension:** 测试覆盖
- **File:** `backend/tests/`
- **Description:** 现有 6 个测试文件（约 600 行），但缺少关键安全场景：普通用户尝试修改 /me 的敏感字段、并发创建同 slug、platform_admin 跨租户操作审计。
- **Fix:** 添加安全边界测试。

### H-9: AgencyAuthorization 缺少复合索引
- **Dimension:** 数据模型 / 性能
- **File:** `backend/app/models/tenant.py:199-220`
- **Description:** `AgencyAuthorization` 表的常用查询（agency_tenant_id + status, client_tenant_id + status）缺少复合索引。（与 auth 模块 H-7 重复发现）
- **Fix:** 添加 `ix_agency_auth_agency_status` 和 `ix_agency_auth_client_status` 复合索引。

## Medium Findings

### M-1: soft_delete_tenant 返回值语义不明确
- **Dimension:** 代码质量
- **File:** `backend/app/services/tenant.py:187-193`
- **Description:** 函数返回 `bool`，但 API 层将 `False` 统一解释为 "Tenant not found"。实际上租户已经处于 terminated 状态也返回 False。
- **Fix:** 返回 `Tenant | None`，或区分 "not found" 和 "already terminated"。

### M-2: TenantUpdate schema 过于宽松
- **Dimension:** API规范
- **File:** `backend/app/schemas/tenant.py:27-42`
- **Description:** `TenantUpdate` 允许将 `name` 设为 `None`（跳过更新），但不验证 `tenant_type` 的枚举值合法性。`compliance_settings` 和 `quota` 是 dict 类型，无 schema 验证。
- **Fix:** 为 `tenant_type` 添加枚举验证，为 `quota` 和 `compliance_settings` 添加 dict schema。

### M-3: slug 唯一性未在 Service 层校验
- **Dimension:** 安全性
- **File:** `backend/app/services/tenant.py:22-37`
- **Description:** `create_tenant` 依赖数据库的 `UniqueConstraint` 处理 slug 冲突，但未提前校验。如果 slug 冲突，会抛出原始数据库错误而非友好提示。
- **Fix:** 在 service 层先查询 slug 是否已存在，存在则抛出友好错误。

### M-4: list_tenants 搜索使用 LIKE '%xxx%' 无法利用索引
- **Dimension:** 性能
- **File:** `backend/app/api/v1/tenants.py:85-87`
- **Description:** `Tenant.name.ilike(f"%{escaped}%", escape="\\")` 前缀通配符导致无法使用 B-tree 索引。大数据量时搜索性能差。
- **Fix:** 考虑使用 PostgreSQL 的 `pg_trgm` 扩展或全文搜索。

### M-5: Organization.parent_id 缺少索引
- **Dimension:** 数据模型
- **File:** `backend/app/models/tenant.py:83`
- **Description:** `Organization.parent_id` 是自引用外键，树形结构查询会全表扫描。
- **Fix:** 添加 `index=True`。

### M-6: get_tenant 频繁调用无缓存
- **Dimension:** 性能
- **File:** `backend/app/services/tenant.py:98-100`
- **Description:** `get_tenant` 在每个 /me 端点和许多中间件中都被调用，但每次都查询数据库。租户信息变更不频繁，适合缓存。
- **Fix:** 添加 Redis 缓存（TTL 5-10 分钟），租户更新时清除缓存。

### M-7: create_tenant 中 template_id 校验不够健壮
- **Dimension:** 代码质量
- **File:** `backend/app/services/tenant.py:68-72`
- **Description:** `if 0 <= template_id < len(ALL_TEMPLATES)` 依赖 ALL_TEMPLATES 列表长度，未处理列表为空的情况，且 import 在函数内部。
- **Fix:** 添加更严格的校验，或使用模板 ID 映射。

### M-8: brands 页面与 tenant 管理概念混淆

### M-9: 前端 settings/tenant 缺少 contact_email 字段

### M-10: list_tenants 的 count 和 data 查询分开执行
- **Dimension:** 性能
- **File:** `backend/app/api/v1/tenants.py:89-93`

### M-12: onboarding step API 缺少输入验证

### M-13: Tenant.organizations 关系使用 lazy="selectin"

- **Fix:** 改为 `lazy="raise"` 并在需要时显式 `selectinload`。

### M-14: 缺少租户恢复（restore）功能

### M-15: 前端功能开关枚举硬编码
- **Dimension:** 前后端一致性
- **File:** `frontend/apps/admin/src/app/(dashboard)/settings/tenant/page.tsx:202`

### M-16: TenantUpdate 允许将 name 设为空字符串

- **File:** `backend/app/schemas/tenant.py:28`
- **Description:** `TenantUpdate.name` 的 `min_length=1` 允许只包含空格的名称通过验证。
- **Fix:** 添加 strip 验证或使用 `min_length=1, pattern=r"\S"` 确保非空白。

## Technical Decisions

| Decision | Rationale |
|----------|-----------|
| Tenant 不继承 TenantModel | Tenant 是根实体，没有 tenant_id，直接继承 Base |
| Tenant.organizations lazy="selectin" | 大多数场景需要组织列表，但可能过度加载 |
| slug 自动生成 | 未提供 slug 时从 name 自动生成，用户体验好 |
| 软删除而非硬删除 | 标记为 terminated 而非物理删除，数据可恢复 |
| template_id 应用模板 | 创建时可选应用行业模板，灵活性好 |
