## Critical Findings

### C-1: confirm_reset_password 缺少 tenant_id 过滤（跨租户风险）
- **Dimension:** 安全性
- **File:** `backend/app/api/v1/auth.py:432`
- **Description:** `confirm_reset_password` 函数查找账户时仅按 `Account.id` 查询，未添加 `tenant_id` 过滤。虽然密码重置 token 由管理员生成且存有 account_id，但验证环节缺少租户隔离，理论上允许跨租户密码重置攻击。
- **Fix:** 在查询中添加 `tenant_id` 条件，或从 Redis 记录中获取并验证 tenant_id。

### C-2: API 层包含大量业务逻辑（四层分离违规）
- **Dimension:** 代码质量 / 架构
- **File:** `backend/app/api/v1/auth.py:83-147,156-211,394-460`
- **Description:** `login`、`refresh`、`confirm_reset_password` 三个核心函数各含 60-80 行业务逻辑，包括：速率限制、账户锁定、密码验证、JWT 创建、审计日志等。这些应抽取到 Service 层。同样，`password.py` 中的 `change_password` 和 `reset_password` 也直接操作 Model。
- **Fix:** 创建 `AuthService` 和 `AccountService`，将业务逻辑从 API 层迁移至 Service 层。

### C-3: Agency 上下文切换前端 UI 缺失
- **Dimension:** 功能完整性
- **File:** `frontend/apps/admin/src/lib/auth.ts:89-110`
- **Description:** 后端 `agency_auth.py` 已实现 Agency 授权 CRUD 和上下文切换 API（switch-context / exit-context），前端 `auth.ts` 中也有 `switchAgencyContext` / `exitAgencyContext` 方法，但 dashboard 布局中缺少 Agency 切换的 UI 组件。用户登录后无法通过界面进行上下文切换。
- **Fix:** 在后台布局顶部导航栏添加 Agency 切换下拉菜单。

### C-4: /reset-password 接口可被已认证用户滥用
- **Dimension:** 安全性
- **File:** `backend/app/api/v1/password.py:54-67`
- **Description:** `/api/v1/auth/reset-password` 仅依赖 `get_current_tenant` 鉴权，但未验证操作者是否有管理员角色或是否为账户所有者。任何已认证用户只需知道 `account_id` 即可重置他人密码。
- **Fix:** 添加角色校验（admin/platform_admin）或要求输入旧密码。

## High Findings

### H-1: change_password 缺少 tenant_id 验证
- **Dimension:** 安全性
- **File:** `backend/app/api/v1/password.py:42`
- **Description:** `change_password` 函数仅按 `Account.id` 查询，未验证 `tenant_id`。虽然 `account_id` 来自 JWT，但在多租户环境下应保持一致的隔离模式。

### H-2: LoginRequest.password 最小长度为 1
- **Dimension:** 安全性
- **File:** `backend/app/api/v1/auth.py:62`
- **Description:** `LoginRequest` 的 `password` 字段 `min_length=1`，过于宽松。虽然不影响密码存储安全（注册/重置时有强度验证），但可能允许无效登录请求消耗服务器资源。

## Technical Decisions

| Decision | Rationale |
|----------|-----------|
| bcrypt 用于密码哈希 | 安全性高，内置盐值，抗 GPU 破解 |
| JWT + HttpOnly Cookie 双写 | localStorage 方便 axios 拦截器，cookie 方便 middleware 路由守卫 |
| Refresh Token 轮换 | 旧 token 加入 Redis 黑名单，防止重放攻击 |
| 时序攻击防护 | login 函数使用恒定时间密码验证，错误消息统一 |
| IP 速率限制 (Redis) | 轻量级、分布式友好，使用滑动窗口 |
| JWT jti 使用 uuid4 | 不可预测性优先于时间排序，适合 token 唯一标识 |
