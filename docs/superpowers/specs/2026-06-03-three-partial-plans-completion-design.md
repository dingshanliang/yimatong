# 三个部分完成计划的补齐设计

日期：2026-06-03
状态：已批准
关联：三个已有实施计划的补齐范围确认

## 背景

`superpowers/plans/` 中有三个标记为 ⏸ Partial 的计划，完成度 70%-90%。本设计确认每个计划的补齐范围，按"快赢优先"原则分三个 Wave 推进。

## Wave 1：工作台 UX 改进（85% → 100%）

**源计划**：`2026-06-02-dashboard-ux-improvements.md`
**目标**：修复用户旅程审查发现的 2 个 Critical、5 个 Moderate 问题

### 补齐范围（4 项）

#### 1.1 刷新按钮
- **位置**：Dashboard 顶部操作区
- **实现**：添加刷新 IconButton，点击触发 SWR `mutate` 重新拉取所有统计 API
- **反馈**：刷新时按钮显示 loading 旋转，完成后短暂显示成功图标

#### 1.2 表格行点击导航
- **范围**：活动表格、码批次表格、窜货线索表格等主要列表
- **实现**：Ant Design Table 的 `onRow` 配置，点击行跳转详情页
- **视觉**：鼠标悬停行高亮 + cursor pointer

#### 1.3 同比对比指标
- **位置**：每张统计卡片底部
- **显示**："较上周 +12%" 或 "较上月 -5%"，绿色正数、红色负数
- **后端**：analytics API 新增 `comparison` 字段，返回当前值和对比期值
- **时间粒度**：根据筛选的日期范围自动选择对比期（日→昨日、周→上周、月→上月）

#### 1.4 SSE 自动重连
- **范围**：风控实时推送（Risk Dashboard SSE 连接）
- **策略**：指数退避重连（1s → 2s → 4s → 8s → max 30s）
- **UI 反馈**：断线时顶部显示"实时推送已断开，正在重连..."横幅
- **重连成功**：自动恢复订阅，横幅消失

### 不做的
- useCallback 性能优化（YAGNI，等有性能问题再处理）

## Wave 2：扫码统计 UX 改进（90% → 100%）

**源计划**：`2026-06-02-scan-stats-ux-improvements.md`
**目标**：修复扫码统计模块的 3 个严重、5 个中等问题

### 补齐范围（3-4 项）

#### 2.1 Campaign Analytics 加载态
- **位置**：活动分析页的所有数据卡片
- **实现**：补齐 loading skeleton，确保每个 API 请求期间显示占位动画
- **统一**：使用 Ant Design `Skeleton` 组件，与页面其他部分风格一致

#### 2.2 SSE Ticket 认证验证
- **范围**：scan_token JWT 的生成和验证逻辑
- **实现**：
  - 验证 resolver 颁发的 scan_token 是否正确签名、未过期
  - H5 后续请求（权益领取、留资等）携带 scan_token 时正确校验
  - 补充单元测试覆盖 token 过期、签名错误、缺失等场景

#### 2.3 Stats 页面布局调整
- **调整**：日期选择器上移至统计卡片区域上方，作为全局筛选器
- **布局**：筛选器行 → 统计卡片 → 趋势图表 → 明细表格
- **响应式**：移动端日期选择器折叠为单行

#### 2.4 剩余 Issue 审查
- 回溯原始计划，定位未修复的 2 个 issue
- 按严重程度决定是否在本轮修复或记录为 backlog

## Wave 3：渠道闭环补齐（70% → 闭环）

**源计划**：`2026-06-01-channel-region-closed-loop.md`
**目标**：让渠道管理形成完整业务闭环

### 设计决策

**门店模块开关**：部分客户有门店（三级：经销商→区域→门店），部分只有经销商（两级）。通过租户配置控制门店模块的可见性。

### 补齐范围（Step 1 核心闭环）

#### 3.1 门店模块开关
- **配置位置**：`Tenant.enabled_features` JSON 字段，新增 `channel_store` 布尔开关
- **前端行为**：
  - `channel_store = true`：渠道管理显示三级 Tab（经销商/区域/门店）
  - `channel_store = false`：隐藏门店 Tab，码流向登记不出现门店选项
- **默认值**：新租户默认 `false`（减少复杂度）
- **API**：平台管理后台的租户编辑页可切换此开关

#### 3.2 经销商门户前端
- **路由**：`/channels/portal/distributor`
- **数据源**：已有 API `GET /api/v1/channels/portal/distributor/summary`
- **展示**：
  - 经销商维度的扫码统计（总量、趋势图、Top 产品）
  - 码流向列表（收到的码批次、数量、时间）
  - 管辖门店列表（如开启了门店模块）
- **权限**：通过 AccountChannelScope 控制经销商只能看到自己的数据

#### 3.3 门店门户前端
- **路由**：`/channels/portal/store`
- **数据源**：已有 API `GET /api/v1/channels/portal/store/summary`
- **展示**：
  - 门店维度的扫码统计（总量、今日扫码、趋势图）
  - 关联码批次列表
- **权限**：通过 AccountChannelScope 控制门店只能看到自己的数据

#### 3.4 窜货预警闭环
- **流程**：窜货线索自动生成 → RiskNotification 通知 → 品牌方处理 → 经销商门户可查看
- **实现**：
  - DiversionClue 创建时自动生成 RiskNotification（通知相关经销商账号）
  - 品牌方在窜货线索页可标记处理结果（确认窜货/误报/已处理）
  - 经销商门户增加"预警记录"Tab，查看涉及自己的窜货线索
- **通知方式**：站内通知（已有 RiskNotification 模型），后续可扩展邮件/企微

### 不做的（Step 2 后续）
- 高级渠道分析看板（跨经销商对比、趋势预测）
- 完整 E2E 测试套件
- 渠道维度 ROI 分析

## 执行顺序

```
Wave 1（工作台 UX）→ Wave 2（扫码统计 UX）→ Wave 3（渠道闭环）
    ~4 项改动              ~3-4 项改动            ~4 项改动
```

先收尾两个高完成度计划，再做渠道闭环。
