# 演示数据增强设计

> 日期：2026-06-02
> 状态：已批准

## 背景与目标

产品演示缺少丰富的数据，仪表板、图表和列表页面显得空旷，无法展示平台真实运营效果。需要创建一套**中等规模、真实感强**的演示数据，主要面向潜在客户（品牌方）演示，兼顾投资人展示和内部开发测试。

## 设计原则

1. **相对时间**：所有时间戳基于「当前时间」动态生成，每次重置数据都像正在运营
2. **增长趋势**：扫码量、会员数等指标呈上升趋势，体现业务增长
3. **真实分布**：环境占比（微信 65%、H5 20%、支付宝 10%、其他 5%）、地域分布符合中国消费市场特征
4. **幂等安全**：重复运行不会产生重复数据，支持清理后重建
5. **独立脚本**：新建 `backend/scripts/seed_demo.py`，不影响现有 `seed.py`

**时间分布模式**：
- 工作日扫码量高于周末（约 1.5:1）

**首扫/复扫比例**：首扫 70%、复扫 30%

**User-Agent 池**（模拟真实设备）：

## 技术实现

### 文件结构

```
backend/scripts/
  seed_demo.py          # 主脚本（CLI 入口）
```

同时在现有 `backend/app/cli/seed.py` 中增加一个 `demo` 命令，委托调用新脚本。

### CLI 命令

```bash
# 方式一：直接运行脚本
cd backend && python scripts/seed_demo.py

# 方式二：通过现有 CLI
cd backend && python -m app.cli seed demo
```

### 生成策略

1. **品牌/产品/SKU**：使用 `_ensure_*` 模式（存在则跳过），幂等安全
2. **码批次**：使用 `create_code_batch()` + `activate_batch()` 服务层接口
3. **扫码事件**：批量 INSERT，使用 `bulk_insert_mappings` 或 `db.add_all` 提高性能
4. **消费者**：使用预定义的昵称池和城市池随机组合
5. **统计**：最后调用 `aggregate_daily_stats` 按天聚合

### 性能考虑

- 批量插入码和扫码事件（每 1000 条 flush 一次）
- 总数据量控制在 ~20,000 行扫码事件以内，初始化时间预计 < 2 分钟
- 支持幂等运行：先检查是否已有数据，有则跳过或更新

### 数据清理

提供 `--clean` 参数，删除所有演示数据（通过 tenant slug `demo` 定位）。
