# 工作台与看板体系重新设计

> **状态**: 已审批，待实施
> **日期**: 2026-06-03
> **范围**: 工作台首页 + 扫码统计 + 活动看板 + GMV 归因 + 风控看板 + 导出管理

## 1. 问题诊断

### 1.1 信息架构碎片化

当前 7 个独立看板页面（工作台、扫码统计、活动看板、GMV 归因、风控看板、导出管理、区域品牌看板），用户需要理解 7 个不同的页面才能拼凑出完整的业务全貌。

### 1.2 功能高度重复

工作台首页和扫码统计页面的功能重复度约 80%：都展示扫码量、趋势图、日期筛选、数据导出。

### 1.3 缺少 PRD 要求的核心指标

PRD BI-01（P0 优先级）要求经营看板覆盖：**扫码、用户、领券、留资、加私域、跳转、GMV 归因**。当前工作台首页只覆盖「扫码」维度，转化漏斗的下半段（领券→留资→加私域→购买）完全缺失。

### 1.4 工作台缺少行动引导

好的 SaaS 工作台（Shopify、HubSpot、有赞）都具备：今日待办/异常提醒、一眼看健康、快速行动入口。当前工作台是纯数据展示页，没有行动引导。

## 2. 设计方案：大整合

### 2.1 核心决策

将 7 个页面整合为 4 个页面，消除重复，补充缺失，建立清晰的信息层次。

### 2.2 新信息架构

```
侧边栏「数据统计」菜单（旧 → 新）：

旧（5 个二级菜单）             新（3 个一级项 + 1 个独立项）
├── 扫码统计        ❌         📊 经营看板（= 新工作台首页）
├── 活动看板        ──────┐
├── GMV 归因        ──────┤──→ 📈 深度分析（Tab 页签模式）
├── 风控看板        ──────┼──→ 🛡️ 风控中心（改名）
├── 导出管理        ──────┴──→ 📤 数据导出（不变）
```

**区域品牌看板**保留在「渠道组织」→「区域品牌」下，不纳入本次调整。

### 2.3 变更汇总

| 变更 | 原因 |
|------|------|
| 工作台 + 扫码统计 → 经营看板 | 功能重复 80%，合并后成为真正的"主页" |
| 活动看板 + GMV 归因 → 深度分析 | 都是活动维度的下钻分析，适合放一起 |
| 风控看板 → 风控中心 | 改名，保留全部功能，顶部新增概览指标条 |
| 导出管理 → 数据导出 | 不变，仅位置调整 |

## 3. 经营看板（新工作台）详细设计

### 3.1 整体布局：6 个区域

```
┌─────────────────────────────────────────────────────────┐
│ Area 1: 状态提醒栏                                       │
│ ⚠️ 码余量仅剩 1,200  ▶ 活动A转化率周环比下降23%  🟢 3活动进行中│
├─────────────────────────────────────────────────────────┤
│ Area 2: 核心转化漏斗                                      │
│ 扫码 ──→ 领券 ──→ 留资 ──→ 加私域 ──→ 复购/购买             │
│ 12,580   3,142   1,890    956       328                 │
│  100%    25.0%   15.0%    7.6%      2.6%                │
├────────┬─────────┬──────────┬──────────┬────────────────┤
│ 今日   │  本周    │  本月    │  累计    │  环比变化        │
│ 扫码UV │  扫码UV  │  扫码UV  │  首扫    │  ↑↓              │
├────────┴─────────┴──────────┴──────────┴────────────────┤
│ Area 3: 趋势图（扫码量 + 转化率双轴）                       │
├────────────────────────┬────────────────────────────────┤
│ Area 4: 活动排行 Top 5  │ Area 5: 渠道健康 Top 5          │
│ 按转化率降序，可点击跳转   │ 健康评分+异常率，可点击跳转       │
├────────────────────────┬────────────────────────────────┤
│ Area 6a: 快速操作       │ Area 6b: 最近动态               │
│ 创建码/创建活动/导出     │ 最近 5 条业务事件时间线          │
└────────────────────────┴────────────────────────────────┘
```

### 3.2 Area 1：状态提醒栏

**目的**：品牌主/运营打开系统后立刻知道"今天要关注什么"。

| 提醒类型 | 示例 | 级别 | 可点击跳转 |
|---------|------|------|-----------|
| 码余量预警 | "码余量仅剩 1,200，建议尽快补充" | ⚠️ 黄色 | `/codes` |
| 活动异常 | "活动A 转化率周环比下降 23%" | 🔴 红色 | `/analytics/campaigns?id=xxx` |
| 活动状态 | "3 个活动进行中，1 个即将到期" | 🟢 绿色 | `/campaigns` |
| 套餐提醒 | "套餐将于 15 天后到期" | ⚠️ 黄色 | `/settings/tenant` |

**数据来源**：新增 `GET /analytics/alerts` API。

**展示规则**：
- 无提醒时隐藏此区域
- 最多同时展示 5 条，按级别排序（红→黄→绿）
- 每条提醒可点击跳转到对应管理页面

### 3.3 Area 2：核心转化漏斗

**目的**：完整覆盖 PRD BI-01 的转化指标，让品牌主一眼看到"投入→产出"全链路。

| 漏斗环节 | 指标名称 | 数据来源 | 计算逻辑 |
|---------|---------|---------|---------|
| 扫码 | 扫码总量 | scan_events | COUNT WHERE 时间范围内 |
| 领券 | 领券量 / 领券率 | benefit_claims | COUNT / 扫码总量 × 100% |
| 留资 | 留资量 / 留资率 | consumer_profiles | COUNT(phone IS NOT NULL) / 扫码总量 × 100% |
| 加私域 | 加私域量 / 加私域率 | scan_events (redirect action) | COUNT(action=redirect) / 扫码总量 × 100% |
| 复购/购买 | 归因 GMV / 复购率 | external_orders + attribution | 聚合归因订单金额 |

**展示形式**：
- 水平漏斗图，每环节显示绝对值和转化率
- 颜色渐变：蓝→绿→黄→橙→红，直观表示漏斗收窄
- 下方 4 个统计卡片（今日/本周/本月/累计），每个带环比变化箭头

**数据来源**：新增 `GET /analytics/conversion-funnel` API + 增强 `GET /analytics/dashboard` API。

### 3.4 Area 3：趋势图

**变更**：从纯扫码量柱状图升级为**扫码量（柱）+ 转化率（线）双轴图**。

- 默认展示近 30 天（可自定义时间范围）
- 左 Y 轴：扫码量（柱状）
- 右 Y 轴：领券率或综合转化率（折线）
- 底部带日期范围选择器

### 3.5 Area 4：活动排行 Top 5

**目的**：让运营一眼知道哪个活动表现好，引导下钻。

- 按转化率（定义为「领券量/扫码量」，即领券率）降序排列
- 展示活动名称、扫码量、转化率
- 点击跳转「深度分析 → 活动分析」对应活动
- 数据来源：新增 `GET /analytics/campaign-ranking` API

### 3.6 Area 5：渠道健康 Top 5

**目的**：提前发现渠道问题，引导关注风控。

- 展示渠道名称、健康评分、异常率
- 默认按「经销商」维度展示，可通过下拉切换为「区域」或「门店」
- 异常渠道标红
- 点击跳转「风控中心」
- 数据来源：复用现有 `GET /channel-analytics/health-scores` API

### 3.7 Area 6：快速操作 + 最近动态

**Area 6a 快速操作**：
| 操作 | 跳转 |
|------|------|
| 🆕 创建码批次 | `/codes` (创建模式) |
| 🎁 创建营销活动 | `/campaigns` (创建模式) |
| 📤 导出数据 | 触发导出弹窗 |
| 📋 查看全部活动 | `/analytics/campaigns` |

**Area 6b 最近动态**：
- 展示最近 5 条业务事件时间线
- 事件类型：扫码激增、活动状态变更、渠道异常、新增留资等
- 数据来源：新增 `GET /analytics/recent-events` API

## 4. 深度分析详细设计

### 4.1 合并策略：Tab 页签模式

```
┌──────────────────────────────────────────────────┐
│ 📈 深度分析   [ 活动分析 ]  [ GMV 归因 ]             │
├──────────────────────────────────────────────────┤
│ Tab 1 或 Tab 2 的内容                               │
└──────────────────────────────────────────────────┘
```

### 4.2 Tab 1：活动分析

保留现有活动看板的全部功能，并增强：

| 功能 | 说明 | 数据来源 |
|------|------|---------|
| 活动筛选 + 日期范围 | 保留现有筛选 | - |
| 核心指标卡片 | 总扫码/UV/首扫/复扫 | `campaign-scan-stats` |
| 活动漏斗 | 单个活动的转化漏斗，对比全局平均 | `campaign-dashboard` + 新增漏斗数据 |
| 扫码趋势 | 日扫码趋势 + 同期对比 | `campaign-scan-stats` |
| 多活动对比（新增） | 横向对比 Top N 活动的转化率 | `campaign_comparison` |
| 码批次激活进度 | 保留现有的激活/绑定统计 | `code-stats` |
| Excel 导出 | 保留 | `exports` |

### 4.3 Tab 2：GMV 归因

**保持不变**。GMV 归因的 4 个子 Tab（GMV 看板、外部订单、归因记录、ROI 报表）原样迁移。

## 5. 风控中心详细设计

**改名不改功能**。保留全部现有功能，仅新增顶部概览指标条：

| 指标 | 说明 | 数据来源 |
|------|------|---------|
| 待处理告警数 | 实时告警中未处理的数量 | SSE `alerts/stream` |
| 未处理窜货线索 | 未标记已处理的线索数 | `diversion-summary` |
| 渠道平均健康评分 | 所有渠道健康评分均值 | `health-scores` |

## 6. 后端改造范围

### 6.1 新增 API

| API | 方法 | 说明 | 工作量 |
|-----|------|------|--------|
| `/analytics/conversion-funnel` | GET | 转化漏斗数据聚合 | 中 |
| `/analytics/alerts` | GET | 状态提醒（码余量/活动异常/套餐到期） | 中 |
| `/analytics/campaign-ranking` | GET | 活动排行（按转化率 Top N） | 小 |
| `/analytics/recent-events` | GET | 最近业务事件时间线 | 小 |
| `/analytics/dashboard` | GET（增强） | 现有 API 增加转化指标字段 | 小 |

### 6.2 复用现有 API

以下 API 全部复用，不需要重建：
- `GET /analytics/scan-stats` — 扫码统计
- `GET /analytics/campaign-scan-stats` — 活动扫码统计
- `GET /analytics/campaign-dashboard` — 活动看板
- `GET /channel-analytics/health-scores` — 渠道健康评分
- `GET /channel-analytics/scan-by-channel` — 渠道扫码
- `GET /risk-dashboard/*` — 风控全套 API
- `POST /analytics/exports` — 数据导出

### 6.3 数据库变更

不需要新增表。转化漏斗数据通过聚合现有表实现：
- scan_events → 扫码量
- benefit_claims → 领券量
- consumer_profiles → 留资量
- scan_events (redirect action) → 加私域量
- external_orders + attribution → GMV

建议后续可考虑增加 `daily_conversion_stats` 汇总表优化性能（P2）。
